# Manual Firebase setup

1. **Create a project and web app.** In Firebase Console, create a project, then open Project settings → General → Your apps and register a Web app. Copy its web config into a local `.env.local` using `.env.example` as the key list (`VITE_FIREBASE_API_KEY`, auth domain, project ID, app ID, and sender ID). These are public client values, not access control. Vite embeds them at build time; Firebase Hosting does not inject them at runtime. Never add service-account JSON, private API keys, or server credentials to this browser app.
2. **Enable sign-in.** In Authentication → Sign-in method, enable Anonymous. Jeda uses an anonymous UID to scope optional history; it does not implement a mock login.
3. **Create Firestore.** Create a database in the intended region, then publish `firestore.rules` in Firestore → Rules. The rules require authentication and constrain reads/writes to each user's `users/{uid}/checks` collection. Do not switch to test-mode rules.
4. **Enable Firebase AI Logic.** Choose an available Gemini Developer API or Vertex AI backend and complete the Firebase Console setup. Confirm the web app is allowed to call Firebase AI Logic. Jeda sends inference requests directly from the browser; it does not use an application server as a model proxy.
5. **Publish Remote Config.** Create the four parameters in `remoteconfig.defaults.json`: `defaultMode` = `PREFER_ON_DEVICE`, `maxOnDeviceChars` = `1800`, `escalationEnabled` = `true`, `lowConfidenceThreshold` = `2`. Publish the template. The client validates the values and uses the same safe defaults when fetch/activation fails.
6. **Set up App Check.** In Firebase Console, open App Check → Apps, register the web app with reCAPTCHA Enterprise, and set its public site key as `VITE_RECAPTCHA_SITE_KEY`. For local development, use a separate Firebase development project and keep the same provider setup; set `VITE_APPCHECK_DEBUG=true`, restart Vite, copy the Firebase App Check debug token printed in the browser console, then add it under App Check → Apps → your web app → Debug tokens. Never use a debug token in production. Start with monitoring, verify valid requests, then enforce App Check for Firebase AI Logic, Cloud Firestore, and other enabled products. Jeda disables cloud-capable modes and Firestore history until App Check initializes; on-device-only inference remains available with Firebase web config.
7. **Enable device inference for the demo.** Use desktop Chrome 139 or newer. Visit `chrome://flags/#prompt-api-for-gemini-nano-multimodal-input`, enable the flag, and restart Chrome. The on-device model is downloaded on first initialization; Jeda calls Firebase AI Logic's `initializeDeviceModel()` from a user action and shows download progress. Browser, device, free disk, model availability, and policy can affect support. If initialization fails in `ONLY_ON_DEVICE`, the message is not sent to cloud.
8. **Run and verify.** Install packages, start Vite, and open the local URL. Check one synthetic scam example and one benign example. Confirm the badge reflects the response's actual `inferenceSource`, the privacy toggle blocks all cloud fallback, the opt-in history checkbox is off by default, and clearing history works. Use Evaluation only with synthetic cases and explicitly approve its cloud pass.
9. **Build and deploy.** With `.env.local` populated, create the production bundle so Vite embeds the public web-app values and reCAPTCHA site key. Select the correct Firebase project in the Firebase CLI, then deploy Firestore rules and Hosting using the included `firebase.json`. The exact commands (`pnpm build`, `firebase deploy --only hosting`) and the domain steps for App Check and the API key are in the README section "Deploy to Firebase Hosting". Keep API restrictions and App Check enforcement enabled. Do not treat client-side Remote Config or the text detector as a security boundary.
10. **Publish the submission repository.** Create an empty repository on GitHub or GitLab, then add it as a remote and push (`git remote add origin <repo-url>`, `git push -u origin main`; replace any old Vercel remote with `git remote set-url origin <repo-url>`). Before pushing, run `git status` and confirm `.env.local`, private credentials, and real user data are absent and ignored. On GitHub, open Settings → General → Danger Zone → Change repository visibility and select Public only after reviewing the full commit history. On the repository page, choose About → Edit repository details to set its description/topics; GitHub should detect the included `LICENSE` as Apache-2.0 and show it in the About panel.

## Before a public demo

- Use a dedicated Firebase project and synthetic inputs only.
- Confirm reCAPTCHA Enterprise/App Check is configured and enforce it after testing.
- Review Firestore rules in the Firebase Emulator or Rules Playground with two different anonymous UIDs.
- While online, initialize the device model before testing offline. Test Chrome with and without the on-device model available; verify `ONLY_ON_DEVICE` fails closed and `PREFER_ON_DEVICE` discloses SDK cloud fallback.
- Make the product's data-handling notice visible and explain that pasted messages may contain personal information.
- Do not ask participants to paste real recovery phrases, keys, wallet addresses they consider private, or account data.
